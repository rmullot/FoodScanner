FoodScanner, accessible today

How the app actually behaves, screen by screen: what VoiceOver reads, what increased contrast triggers, what the text-size slider does against the system setting. Reflects the repo's code, not a proposal.

19 pt body minimum 44–60 pt targets Dynamic Type → AX5 Color + pattern + text
Architecture

Pure SwiftUI, App/TabView lifecycle from RootView. Scanner tab on ScannerCoordinator + Router<ScannerRoute>; History still keeps a local NavigationPath.

Contrast and motion

No in-house switch: increased contrast reads colorSchemeContrast, system reduce-motion is read-only, an app-only toggle fills the gap where the system doesn't let the app turn it on.

Dynamic Type

Settings' slider recalibrates against the system category on every launch, foreground return, or iOS change — it never falls below the system, never an inconsistent duplicate.

The journey

Six screens, light theme / spring-summer palette. Each mockup reuses the FoodScannerUI components actually used in the matching view, and the exact strings from Localizable.strings — shown here in French, the app's source locale.

6 · Settings — SettingsScreenView

Contrast and "reduce animations" (when forced by the system): read-only FSStatusRow. Otherwise an FSToggleRow. FSTextSizeSlider disables itself and explains why as soon as the system is already at its maximum size.

Contrast and motion — the real system signal

Neither increased contrast nor system reduce-motion is an in-house setting: both are read straight from iOS. The app only adds a toggle where iOS doesn't let it act from inside the app itself.

Increased contrast

@Environment(\.colorSchemeContrast) == .increased drives everything: thickened borders (FSMetrics.borderWidth(for:)/borderWidthStrong(for:)), switch to fsBorderStrong / fsAccentSoftStrong, bumped font weight (Font.fsBodyHeavy). Settings only shows a status and a shortcut to iOS; the Nutri-Score never changes.

Reduce motion

The system signal accessibilityReduceMotion is read-only on the SwiftUI side. When it's already on, Settings shows it as a status; otherwise an FSToggleRow drives an app-only EnvironmentKey (appReduceAnimations) read by .appAnimation() — the two signals are OR-combined everywhere in the app.

Every change is announced

Flipping a system status while Settings is open moves VoiceOver focus onto it (@AccessibilityFocusState) and fires FSAnnounce.say(...) — which only speaks while VoiceOver is running, with a 0.35 s delay to let focus settle.

Dynamic Type: the system always wins

Settings' slider isn't a floor pushed on top of the system — it's a twelve-notch window onto the same scale as UIContentSizeCategory, held in a single table (AppDynamicTypeScale).

Recalibrates, never frozen

recalibrateTextScale() runs on launch, on every return to foreground, and on every system change — in both directions.

Honest ceiling

The slider disables itself and explains why ("Votre appareil utilise déjà la plus grande taille de texte possible" — "Your device is already using the largest available text size") only once the system is already at AX5 — never before.

The keypad holds up at AX5

FSKeypad keeps a minimum height independent from the barcode field; overflow scrolls instead of clipping the bottom row — fixed 2026-09-11 on iPhone SE.
